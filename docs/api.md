# API สำหรับระบบ HIS ของโรงพยาบาล (D19)

ระบบ HIS ของโรงพยาบาลส่งไฟล์ผลตรวจสุขภาพเข้าหน่วยงานกลางผ่าน API แล้วดูสถานะของไฟล์ได้
**ส่งอย่างเดียว:** ผ่าน API ดึงผลตรวจรายคนกลับไปไม่ได้ ดูได้แค่สถานะไฟล์ของโรงพยาบาลตัวเอง

เอกสารแบบกดลองเรียกได้: `https://<โดเมน>/api/v1/docs` (ตอนพัฒนา: http://127.0.0.1:8100/api/v1/docs)

## 1. ขอ API key (เจ้าหน้าที่หน่วยงานกลางทำ)

```bash
python scripts/manage_api_keys.py create --hospital H01 --name "HIS รพ.ตัวอย่าง"
python scripts/manage_api_keys.py list          # ดู key ทั้งหมด (ไม่แสดงตัว key)
python scripts/manage_api_keys.py revoke 3      # ยกเลิก key #3 มีผลทันที
```

- key แสดงครั้งเดียวตอนสร้าง ระบบเก็บแค่ค่า hash ถ้าหายให้ยกเลิกแล้วออกใหม่
- key ผูกกับรหัสโรงพยาบาล ไฟล์ที่ส่งด้วย key นี้เข้าโรงพยาบาลนั้นเสมอ ผู้เรียกระบุโรงพยาบาลเองไม่ได้
- บน server ให้รันในคอนเทนเนอร์: `docker compose exec app python scripts/manage_api_keys.py ...`

## 2. ส่งไฟล์

```bash
curl -X POST https://<โดเมน>/api/v1/files \
     -H "X-API-Key: hism_xxxxxxxx" \
     -F "file=@ผลตรวจสุขภาพ.xlsx"
```

ตอบทันที (`202`) แล้วประมวลผลต่อเบื้องหลัง:

```json
{
  "file_id": 42,
  "filename": "ผลตรวจสุขภาพ.xlsx",
  "status": "processing",
  "message": "ได้รับไฟล์แล้ว กำลังประมวลผล",
  "items_waiting_for_staff": 0,
  "received_at": "2026-09-14T12:00:00",
  "duplicate": false,
  "status_url": "/api/v1/files/42"
}
```

ส่งไฟล์เดิม (เนื้อหาเหมือนเดิมทุกไบต์) ซ้ำ จะได้ `200` พร้อมเลขงานเดิม และ `"duplicate": true` ระบบไม่ประมวลผลซ้ำ
ยกเว้นครั้งก่อนล้มเหลว จะรับเป็นงานใหม่

## 3. ดูสถานะ

```bash
curl https://<โดเมน>/api/v1/files/42 -H "X-API-Key: hism_xxxxxxxx"
curl "https://<โดเมน>/api/v1/files?limit=20" -H "X-API-Key: hism_xxxxxxxx"   # ไฟล์ล่าสุด
```

| `status` | ความหมาย | โรงพยาบาลต้องทำอะไร |
|---|---|---|
| `processing` | กำลังประมวลผล (ปกติไม่ถึงนาที) | ถามใหม่ภายหลัง |
| `awaiting_review` | บันทึกส่วนที่แน่ใจแล้ว ส่วนที่เหลือรอเจ้าหน้าที่หน่วยงานกลางตรวจ (`items_waiting_for_staff` = จำนวนรายการ) | ไม่ต้องทำอะไร |
| `completed` | นำเข้าเสร็จแล้ว | – |
| `failed` | ประมวลผลไม่สำเร็จ เจ้าหน้าที่หน่วยงานกลางจะตรวจสอบ | ส่งใหม่ได้ถ้าได้รับแจ้ง |

## 4. ข้อผิดพลาด

ทุกแบบมีรูปแบบเดียวกัน: `{"detail": {"code": "...", "message": "..."}}`

| HTTP | `code` | สาเหตุ |
|---|---|---|
| 400 | `empty_file` | ไฟล์ว่าง |
| 401 | `missing_key` / `invalid_key` | ไม่มี key, key ผิด หรือถูกยกเลิก |
| 404 | `not_found` | ไม่มีไฟล์นี้ในโรงพยาบาลของ key นี้ |
| 413 | `too_large` | ไฟล์ใหญ่เกินกำหนด |
| 415 | `unsupported_type` | ไม่ใช่ .csv .xlsx .xls |
| 429 | `rate_limited` | เรียกถี่เกินกำหนด (มี header `Retry-After`) |

## 5. Deploy บน server

1. ติดตั้ง Docker แล้วคัดลอกโปรเจกต์และ `.env` (ใส่ `DATABASE_URL`, `OPENROUTER_API_KEY`, `APP_PORT=8000`)
2. `docker compose up -d --build` แอปจะรัน migration เอง และเปิดพอร์ตที่ `127.0.0.1` เท่านั้น
3. ติดตั้ง Caddy ใช้ [deploy/Caddyfile](../deploy/Caddyfile) (แก้โดเมน) Caddy ขอใบรับรอง HTTPS เอง
4. Firewall เปิดแค่ 80/443 (และ SSH) **ห้ามเปิดพอร์ตแอปหรือ Postgres ออกอินเทอร์เน็ตโดยตรง** เพราะ API ภายในของหน้าเว็บเจ้าหน้าที่ไม่มีการยืนยันตัวตน
5. เจ้าหน้าที่ใช้หน้าเว็บผ่านเครือข่ายภายใน หรือ `ssh -L 8000:127.0.0.1:8000 <server>` แล้วเปิด http://127.0.0.1:8000
6. ออก key ให้โรงพยาบาลตามข้อ 1 แล้วทดสอบด้วย `curl` ตามข้อ 2

ค่าที่ปรับได้ใน `.env`:

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `API_MAX_UPLOAD_MB` | 20 | ขนาดไฟล์สูงสุด (Caddy ตั้งไว้ 25 MB) |
| `API_RATE_PER_MIN` | 30 | จำนวน request ต่อนาทีต่อ key |
| `API_MAX_PARALLEL` | 2 | จำนวนไฟล์ที่ประมวลผลพร้อมกัน ที่เหลือต่อคิว |

ข้อจำกัดของ POC: การจำกัดความถี่และคิวงานอยู่ในโปรเซสของแอป จึงต้องรันแอป **1 โปรเซส** ต่อ server
ถ้า server restart ระหว่างประมวลผล ไฟล์ที่ค้างจะถูกรันต่อเองตอนแอปเปิดใหม่

## 6. ความปลอดภัยและข้อมูลส่วนบุคคล

- ผ่าน API ดึงข้อมูลรายคนไม่ได้ ดูได้แค่สถานะไฟล์ของโรงพยาบาลตัวเอง
- ระบบบันทึกว่าไฟล์ไหนมาจาก key ไหน (`source_files.api_key_id`) และเวลาที่ key ถูกใช้ล่าสุด
- AI ได้รับแค่หัวคอลัมน์ หน่วย และค่าตัวอย่าง ไม่ได้รับชื่อหรือเลขบัตร
- **ใช้กับข้อมูลคนไข้จริงต้องผ่านการประเมิน PDPA ก่อน** (docs/requirements.md, นอกขอบเขต POC)
