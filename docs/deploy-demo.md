# Deploy เดโม และเนื้อเรื่องเดโม

เอกสารนี้ใช้กับการ deploy **เพื่อเดโมด้วยข้อมูลทดสอบเท่านั้น** ไม่ใช่การใช้งานจริงกับข้อมูลคนไข้
(สิ่งที่ยังขวางการใช้งานจริงอยู่ท้ายเอกสาร) เขียนเมื่อ 2026-09-22 จากโค้ดที่ commit `30925ab` เป็นต้นไป

**สิ่งที่ตรวจแล้วบนเครื่องพัฒนา:** เนื้อเรื่องเดโมข้อ 7 ทุกขั้น (ซ้อมกับไฟล์จริงของกรมฯ ทั้งโหมดเรียก AI จริงและโหมด `replay`),
คำสั่งสำรอง `pg_dump`, `alembic current`, `scripts/reset_demo.py` (มีเทสอัตโนมัติ), `scripts/create_user.py`,
และผลตอบกลับของแอปต่อเส้นทางที่ต้องปิด (404 หรือ 401)
**สิ่งที่ยังไม่ได้ตรวจ ต้องตรวจบนเซิร์ฟเวอร์จริง:** การตั้งค่า reverse proxy (รหัสผ่านชั้นนอก, การบล็อกเส้นทาง),
การ deploy ลงฐานข้อมูลที่มีข้อมูลเดิม, และผลของ `curl` ในข้อ 5 ผ่าน proxy จริง

## 0. ก่อนเริ่ม: 4 เรื่องที่ต้องรู้

1. **migration 0008 ลบข้อมูลเดิมทิ้งและย้อนกลับไม่ได้** ถ้าฐานข้อมูลบนเซิร์ฟเวอร์ยังเป็นเวอร์ชันก่อน D23
   (ก่อน 2026-09-20) ผลตรวจและพนักงานเดิมจะหายทั้งหมด **สำรองก่อนเสมอ** (ข้อ 2)
2. **เดโมนี้ไม่ส่งข้อมูลออกไปไหน** ปุ่ม "ส่งรายงาน" แค่สร้างไฟล์และบันทึกว่าส่ง กรมฯ ยังไม่มีช่องทางรับ
3. **`/api/v1` ปิดอยู่** (ไม่ได้ mount ในแอป) ระบบ HIS ของโรงพยาบาลส่งไฟล์เข้ามาเองไม่ได้ ต้องอัปผ่านหน้าเว็บ
4. **เส้นทางเก่า `/api/legacy/upload` ปิดเป็นค่าเริ่มต้นแล้ว** (ตอบ 404) ห้ามตั้ง `ENABLE_LEGACY_UPLOAD` บนเซิร์ฟเวอร์

## 1. เตรียมที่เครื่องพัฒนา

```bash
.venv/bin/python -m pytest -q tests          # ต้องผ่านทั้งหมด (204 ตอนเขียนเอกสาร ใช้เวลา 30 วินาที ถึง 2 นาที)
.venv/bin/alembic check                      # ต้องขึ้น "No new upgrade operations detected"
git push origin poc-agents                   # ต้องได้รับอนุญาตจากเจ้าของโปรเจกต์ก่อน
```

คำตอบ AI ที่บันทึกไว้ (`storage/llm_cache/`) **ไม่อยู่ใน git** ต้องคัดลอกไปเซิร์ฟเวอร์เอง (ข้อ 4)
ในนั้นมีเฉพาะชื่อรายการตรวจและค่าตัวอย่าง ไม่มีชื่อคนหรือเลขบัตร

## 2. สำรองบนเซิร์ฟเวอร์ (ข้ามไม่ได้)

```bash
cd <โฟลเดอร์โปรเจกต์บนเซิร์ฟเวอร์>
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' | gzip > backup-$(date +%F-%H%M).sql.gz
tar czf storage-$(date +%F-%H%M).tgz storage/
ls -lh backup-*.sql.gz storage-*.tgz          # ไฟล์ต้องมีขนาด ไม่ใช่ 0
```

ย้อนกลับ ถ้า deploy แล้วมีปัญหา: หยุดแอป คืนฐานข้อมูลจากไฟล์สำรอง แล้วใช้โค้ดเวอร์ชันก่อนหน้า
(ย้อน migration ด้วย `alembic downgrade` ทำไม่ได้ในขั้น 0008)

## 3. ตั้งค่า `.env` บนเซิร์ฟเวอร์

คัดลอกจาก `.env.example` แล้วแก้ค่าเหล่านี้ (`.env` ห้าม commit)

| ตัวแปร | ค่า |
|---|---|
| `POSTGRES_PASSWORD` และ `DATABASE_URL` | รหัสผ่านจริง ห้ามใช้ `change-me` |
| `APP_SECRET` | `openssl rand -base64 48` ถ้าเว้นว่าง ทุก deploy ใหม่ที่ไม่เก็บ `storage/` จะเตะทุกคนออกจากระบบ |
| `OPENROUTER_API_KEY` | คีย์จริง |
| `LLM_MODE` | ตอนซ้อม `live` ตอนเดโมจริง `fallback` (ข้อ 6) |
| `LLM_TIMEOUT_S` | `45` |
| `AUTO_ACCEPT` | `on` |
| `ENABLE_LEGACY_UPLOAD` | **ไม่ต้องตั้ง** |

พอร์ตของแอปและฐานข้อมูลผูกกับ `127.0.0.1` เท่านั้น เข้าจากภายนอกได้ผ่าน reverse proxy เท่านั้น

## 4. Deploy

```bash
git pull                                       # หรือคัดลอกโค้ดขึ้นเครื่อง
mkdir -p storage/llm_cache                     # แล้วคัดลอกคำตอบ AI ที่บันทึกไว้จากเครื่องพัฒนามาไว้ในนี้
docker compose up -d --build
docker compose logs app | grep "Running upgrade"    # ต้องเห็นถึง 0011_profusion_width (ถ้าฐานข้อมูลเก่า)
docker compose exec app alembic current             # ต้องขึ้น 0011_profusion_width (head)
```

อย่ารัน `docker compose up --build` ระหว่างมีการอัปโหลดหรือระหว่างเดโม เพราะทำให้ Postgres restart

สร้างบัญชีผู้ดูแลตัวแรก (รหัสผ่านแสดงครั้งเดียว):

```bash
docker compose exec app python scripts/create_user.py --role superadmin --email <อีเมล> --name <ชื่อ> --surname <นามสกุล>
```

## 5. Reverse proxy และการตรวจหลัง deploy

ตัวอย่างอยู่ที่ `deploy/Caddyfile` (เครื่องจริงใช้ nginx ตาม D22 การตั้งค่าเครื่องจริง **ยังไม่ได้ตรวจ**)
ที่ต้องเป็นจริงไม่ว่าใช้ตัวไหน:

- ทุกหน้าอยู่หลังรหัสผ่านของ proxy **และ** หน้าล็อกอินของแอป
- `/api/legacy/` ถูกบล็อกที่ proxy ด้วย (แอปปิดให้แล้ว แต่ปิดสองชั้น)
- `/docs`, `/openapi.json` ควรถูกบล็อกหรืออยู่หลังรหัสผ่าน เพราะเปิดเผยรายชื่อ API ทั้งหมด
- โฟลเดอร์ `storage/` เป็น volume ถาวร (เก็บไฟล์ต้นฉบับที่อัป และคีย์ session)

ตรวจหลัง deploy (แทน `HOST` ด้วยชื่อเครื่อง และ `USER:PASS` ด้วยรหัสของ proxy):

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://HOST/login                          # ไม่มีรหัส proxy ต้องเป็น 401
curl -s -o /dev/null -w "%{http_code}\n" -u USER:PASS https://HOST/login             # ต้องเป็น 200
curl -s -o /dev/null -w "%{http_code}\n" -u USER:PASS -X POST https://HOST/api/legacy/upload   # ต้องเป็น 404 หรือ 403
curl -s -o /dev/null -w "%{http_code}\n" -u USER:PASS https://HOST/api/reviews       # ไม่ล็อกอินแอป ต้องเป็น 401
curl -s -o /dev/null -w "%{http_code}\n" -u USER:PASS https://HOST/api/v1/files      # ต้องเป็น 404 (ปิดอยู่)
```

จากนั้นเข้าเว็บ ล็อกอิน ไล่กด 3 การ์ดในเมนูหลัก ถ้าทุกหน้าเปิดได้ ถือว่าผ่าน

## 6. ซ้อมก่อนวันเดโม (ต้องทำ)

หน่วยบริการที่ยังไม่เคยส่งไฟล์มาจะถูกถามหลายข้อ และคำตอบที่ระบบเรียนรู้จะทำให้ไฟล์รอบสองผ่านเอง
การซ้อมทำสองอย่าง: บันทึกคำตอบ AI ไว้ใช้สำรอง และให้ผู้พูดรู้ว่าจะเจออะไร

1. ตั้ง `LLM_MODE=live` แล้ว `docker compose up -d`
2. เดินตามเนื้อเรื่องข้อ 7 ให้ครบ ระบบจะบันทึกคำตอบ AI ไว้ใน `storage/llm_cache/`
3. **ล้างข้อมูลซ้อม** (ไม่ล้างแล้วระบบจะจำทุกอย่าง วันจริงไม่มีคำถามให้โชว์):
   ```bash
   docker compose exec app python scripts/reset_demo.py --yes
   ```
   ล้างสถานประกอบการ ทะเบียน รอบ ผลตรวจ คำถาม และสิ่งที่ระบบเรียนรู้ทั้งหมด
   เก็บไว้: พจนานุกรมกลาง ประเภทการตรวจ บัญชีผู้ใช้ และคำตอบ AI ที่บันทึกไว้
4. วันจริงตั้ง `LLM_MODE=fallback` (เรียก AI จริงก่อน ถ้าเน็ตล่มหรือช้ากว่า 45 วินาทีใช้คำตอบที่บันทึกไว้)
   ไม่มีเน็ตเลยใช้ `replay` แล้วรายการที่ไม่มีคำตอบบันทึกจะถูกส่งให้คนตอบ ไม่เดา

## 7. เนื้อเรื่องเดโม (ประมาณ 12 นาที)

ใช้ไฟล์ในโฟลเดอร์ `แก้เลขบัตรแล้ว` (รูปแบบไฟล์จริงของกรมฯ) ทุกขั้นในตารางนี้ **ซ้อมจนจบแล้ว** บนฐานข้อมูลแยก ผ่าน API ตัวเดียวกับที่หน้าจอเรียก
(ขั้น 4 ถึง 9 รันซ้ำในโหมด `replay` ได้ผลเหมือนโหมดเรียก AI จริง) หน้าจอแต่ละหน้าตรวจด้วยเบราว์เซอร์แยกกันไว้แล้ว
แต่ยังไม่ได้คลิกตามเนื้อเรื่องนี้ต่อเนื่องครั้งเดียวจบ **ให้ผู้พูดซ้อมคลิกเองหนึ่งรอบก่อนวันจริง**

| ขั้น | ทำอะไร | ให้ผู้ชมเห็นอะไร (ตัวเลขที่เห็นจริงตอนซ้อม) |
|---|---|---|
| 1 | เมนูหลัก → **รายงานผลตรวจสุขภาพกลุ่มเสี่ยง** | ลำดับที่ต้องทำ 8 ขั้น และวงกลมตัวเลขงานค้าง |
| 2 | **ทะเบียนสถานประกอบการ**: เพิ่มบริษัท + แผนก `ผลิต1` แล้วสร้างการสำรวจและรอบตรวจ | หน้าจอเหมือนคู่มือของกรมฯ วันที่ตรวจมาจากรอบ ไม่ต้องอยู่ในไฟล์ |
| 3 | **นำเข้าทะเบียนพนักงาน** `employee_list_template.xlsx` (เลือกหน่วยบริการ UNSPECIFIED) | เพิ่ม 8 คน **ไม่มีคำถามเลย** อ่านหัวคอลัมน์ของกรมฯ ได้เอง |
| 4 | **นำเข้าผลตรวจ (AI)** `checkup_report_template (ปกติ).xlsx` เข้ารอบที่สร้าง | **เก็บได้ทันที 192 ค่า** ที่รู้จัก และเหลือ **14 คำถาม** |
| 5 | **งานที่ต้องตรวจ** ตอบทีละข้อ (ตารางคำตอบด้านล่าง) | ระบบถามทีละข้อ AI เสนอคำตอบและมี AI ตัวที่สองตรวจ, ข้อไหนไม่แน่ใจ AI ไม่เสนอ ระบบไม่เดาให้ |
| 6 | อัปไฟล์ปกติเดิมเข้ารอบใหม่ (สร้างอีกรอบ) | **ไม่มีคำถามเลย** เก็บครบ 208 ค่า ระบบจำที่ตอบไว้แล้ว |
| 7 | อัป `checkup_report_template (ผิดปกติ).xlsx` เข้ารอบแรก → แท็บ **ข้อมูลขัดแย้ง** | **14 ข้อขัดแย้ง** (เช่น BMI 19.92 เป็น 33.0, ความดันตัวบน 120 เป็น 145) ขึ้นคู่กัน บอกชื่อไฟล์ทั้งสองฝั่ง ไม่ทับเงียบๆ ตัดสินได้ทีละค่าหรือทั้งไฟล์ |
| 8 | รับรองรอบ แล้วตัดสินข้อขัดแย้งข้อหนึ่งเป็น "ใช้ค่าใหม่" | **การรับรองถูกปลดเอง** เพราะผลเปลี่ยน |
| 9 | **ภาพรวมและส่งรายงาน** | ถ้ามีงานค้างส่งไม่ได้ต้องติ๊กยืนยัน เคลียร์แล้วส่ง ดาวน์โหลดไฟล์ 2 ชีต (WBC/PLT หน่วยพัน, ผล 0/1) |

### คำตอบของ 14 คำถามในขั้น 5 (ซ้อมจริงเมื่อ 2026-09-22 ค่า AI $0.007)

| คอลัมน์ในไฟล์ | AI เสนอ | ให้ตอบ | เหตุผลที่พูดกับผู้ชม |
|---|---|---|---|
| `wbc`, `plt` | ไม่เสนอ | **เป็นผลตรวจอย่างอื่น** เลือก WBC/PLT และหน่วย `10^3/µl` | ค่า 4.7 กับ 237 อยู่คนละสเกลกับที่ระบบเก็บ ระบบบังคับเลือกหน่วย |
| `far_lateral_phoria`, `far_vertical_phoria`, `spirometry_obstruction`, `spirometry_restriction`, `spirometry_summary`, `urinalysis` | เก็บเป็นข้อมูลเพิ่มเติม (AI สองตัวเห็นตรงกัน) | **ใช่ ตามที่ AI เสนอ** | ผลตรวจจริงที่ไม่มีช่องในแบบฟอร์ม เก็บไว้ ไม่ทิ้ง |
| `health_examination` | ไม่ใช่ผลตรวจ (มั่นใจสูง) | **ไม่ใช่ผลตรวจ** | ระบบไม่ยอมรับ "ทิ้ง" เองเด็ดขาด ต้องให้คนกด |
| `วันที่ (ปปปป-ดด-วว)` | ไม่เสนอ | **ไม่ใช่ผลตรวจ** | วันที่มาจากรอบอยู่แล้ว |
| `spirometry_fev1`, `spirometry_fvc`, `rbc_che`, `plasma_che_bche` | ไม่เสนอ | **เป็นผลตรวจจริง แต่ไม่มีช่องในแบบฟอร์ม** (เก็บเพิ่มเติม) | **ยังไม่ทราบหน่วยที่กรมฯ ต้องการ** เก็บค่าไว้ไม่เดา รอคำตอบจากกรมฯ |

บอกผู้ชมตรงๆ ว่าคำถามหกข้อถึงกรมฯ (0/1 หรือ 1/2, หน่วยของ `rbc_che`, ผลสไปโรเมทรีเป็นลิตรหรือเปอร์เซ็นต์ ฯลฯ)
ยังรอคำตอบ ระบบเก็บค่าดิบไว้ทุกค่า จึงแก้ย้อนหลังได้ไม่ว่าคำตอบเป็นแบบไหน

## 8. สิ่งที่ต้องบอกผู้ชมตรงๆ

- ข้อมูลทั้งหมดเป็นข้อมูลทดสอบ ไม่มีข้อมูลคนไข้จริง
- **ตัวเลขความแม่นยำและระดับอัตโนมัติในเอกสารเดโมเดิม (`docs/demo.md`) ห้ามนำมาอ้าง** วัดจากโครงข้อมูลก่อน D23
  ตอนนี้ระบบวัดผลยังปิดอยู่ (ดู D23-หนี้) จึงยังไม่มีตัวเลขชุดใหม่ที่อ้างได้
- ยังไม่ส่งข้อมูลถึงกรมฯ จริง และยังรับไฟล์จาก HIS ของโรงพยาบาลโดยตรงไม่ได้
- ตัวเลขของ AI (ค่าใช้จ่ายราว $0.007 ต่อไฟล์แรกของหน่วยใหม่) วัดจากการซ้อมครั้งเดียว ไม่ใช่ค่าเฉลี่ย

## 9. สิ่งที่ยังขวางการใช้งานจริง (ไม่ใช่เดโม)

1. ยังไม่มีการกรองข้อมูลข้ามโรงพยาบาล (D20-หนี้) เจ้าหน้าที่หน่วยหนึ่งเห็นข้อมูลของอีกหน่วยได้
2. ข้อมูลคนไข้จริงต้องผ่าน PDPA ก่อน (D19)
3. คำถามหกข้อถึงกรมฯ ยังไม่มีคำตอบ (D23-ถาม)
4. การวัดผลยังปิด (D23-หนี้) และเส้นทางที่ AI ตัดสินเองยังไม่มีการทดสอบอัตโนมัติบนโครงใหม่
5. `/api/v1` ยังปิด (D19-หนี้)
6. ช่องทางส่งไฟล์ให้กรมฯ จริง ยังไม่มี
